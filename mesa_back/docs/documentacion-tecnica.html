Mesa Partes Virtual

Documentación técnica del backend — Spring Boot 3.2 + JWT + PostgreSQL

Proyecto: com.emtap:mesapartes  |  Java: 17  |  Spring Boot: 3.2.1  |  Puerto: 9000  |  Base de datos: PostgreSQL (sgd-emapat)

Arquitectura

API REST monolitica con capas: Controller → Service → Repository → Entity. Autenticación stateless via JWT.

Cliente (Web/Mobile) → Controller → Service → Repository → PostgreSQL
JWT Filter ↕ SecurityContext ↕ RENIEC / SUNAT API

Seguridad

Autenticación Stateless con JWT

  1. Login: usuario/envía credenciales → POST /api/auth/login
  2. Validación: AuthenticationManager verifica contra BD (BCrypt)
  3. Token: JwtService genera JWT firmado con HS256 + secret
  4. Request: Cliente envía Authorization: Bearer <token>
  5. Filtro: JwtAuthenticationFilter extrae, valida y establece SecurityContext

Filter: JwtAuthenticationFilter

Extiende OncePerRequestFilter. Se ejecuta en cada request antes de UsernamePasswordAuthenticationFilter.

  1. Extrae header Authorization: Bearer <token>
  2. Si no hay token → continúa la cadena (no autenticado)
  3. Extrae username del token via JwtService.getUsernameFromToken()
  4. Carga UserDetails via CustomUserDetailsService.loadUserByUsername()
  5. Valida token con JwtService.validateToken()
  6. Establece UsernamePasswordAuthenticationToken en SecurityContextHolder
  7. Manejo de excepciones: ExpiredJwtException → 401, SignatureException → 401, MalformedJwtException → 400

Notas Técnicas

  • RabbitMQ: La dependencia spring-boot-starter-amqp está incluida pero no hay código que la use. El docker-compose.yml define el servicio listo para usar.
  • Mails: Se usan 2 cuentas SMTP distintas. La cuenta tramite.documentario envía notificaciones internas; la cuenta mesadepartesvirtual envía respuestas al ciudadano.
  • Templates Email: 4 templates HTML en classpath:templates/email/ con variables {{var}}. Usan EmailTemplateLoader para carga y reemplazo.
  • Async: El envío de correos usa @Async (habilitado via @EnableAsync en InicioApplication).
  • Secuencia DB: IDOSGD.SEC_REMITOS_NU_EMI debe existir en la BD. Si no existe, crearla manualmente.
  • @Value: Los valores por defecto de remitos se inyectan desde application.properties (prefijo remito.*).
  • Cache: ListasCacheService carga ubigeos en memoria al iniciar (@PostConstruct).
